# راهنمای وضعیت CDN و کش (CDN & Caching Guide)

این مستند وضعیت فعلی سیستم از نظر اتصال به CDN و استراتژی‌های کشینگ را توضیح می‌دهد.

## وضعیت فعلی (Current Status)

در حال حاضر سیستم در وضعیت **CDN-Ready** قرار دارد. این به این معنی است که زیرساخت نرم‌افزاری و پیکربندی سرور برای پذیرش CDN کاملاً آماده است، اما لزوماً نیازی به وجود یک CDN خارجی (مثل Cloudflare یا ابر آروان) برای کارکرد صحیح ندارد.

### ۱. پیکربندی Nginx
سرور Nginx پروژه (در فایل `proxy/conf.d/default.conf.template`) به گونه‌ای تنظیم شده است که هدرهای لازم برای کشینگ را ارسال کند:
- برای مسیر `/uploads/` (تصاویر و فایل‌های رسانه‌ای)، هدر `Cache-Control` با اعتبار ۳۰ روزه تنظیم شده است.
- هدر `public, no-transform` برای اطمینان از کش شدن صحیح توسط مرورگر و CDNها اضافه شده است.

### ۲. آمادگی برای CDN خارجی
از آنجایی که اکثر سرویس‌های CDN در سطح DNS عمل می‌کنند، فعال‌سازی آن‌ها نیازی به تغییر در کدهای سمت سرور ندارد. شما می‌توانید با تنظیم DNSهای خود روی یک CDN، بلافاصله از مزایای آن بهره‌مند شوید.

### ۳. پشتیبانی از ذخیره‌سازی ابری (S3)
در تنظیمات برنامه (`src/config/index.ts`) و فایل محیطی (`.env`)، متغیر `S3_PUBLIC_URL` پیش‌بینی شده است. اگر در آینده تصمیم بگیرید فایل‌ها را به جای سرور محلی، روی یک Object Storage (مثل Arvan S3 یا AWS S3) قرار دهید و برای آن یک CDN اختصاصی ست کنید، فقط با تغییر این متغیر تمام آدرس‌های تصاویر در API به صورت خودکار اصلاح می‌شوند.

## پیشنهادات (Recommendations)

- **در فاز شروع:** با توجه به بهینه بودن تنظیمات Nginx، استفاده از CDN اجباری نیست و کش محلی مرورگر و Nginx بار سرور را به خوبی مدیریت می‌کند.
- **در فاز رشد:** زمانی که ترافیک ورودی افزایش یافت یا کاربران از نقاط جغرافیایی مختلف به سیستم وصل شدند، پیشنهاد می‌شود یک CDN (ترجیحاً داخلی برای سرعت بیشتر در ایران) فعال کنید. این کار بدون نیاز به تغییر کد (Zero Code Change) قابل انجام است.

## خلاصه فنی
- **کد آماده است؟** بله.
- **نیاز به تغییر کد دارد؟** خیر.
- **Nginx بهینه است؟** بله، با ۳۰ روز کش برای مدیا.
- **انعطاف‌پذیری:** پشتیبانی کامل از URLهای سفارشی برای CDNهای متصل به S3.
